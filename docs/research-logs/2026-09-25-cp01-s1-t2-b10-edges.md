| Question / classification | Answer and rationale |
|---|---|
| Q76 — already specified; coverage missing | Core §15 applies endpoint existence and tuple uniqueness to all relations. R02 and R04 now say so. AC02 adds two missing-endpoint cases on an additional relation, and AC04 gets `core-relation` and `additional-relation` cases. |
| Q77 — ambiguous | Core §45 immutability covers every tuple in the core edge store `specs/graph/edges.yml`. Tuples in an Extension edge file follow that Extension's owning semantics (Core §45). Core §54 limits such a file to the Extension's own relations and to `supersedes` tuples between its own registered node types. A core-to-core `supersedes` there is a foreign tuple (S03/AC13 `core-supersession-edge-in-extension-store`), so core lineage cannot escape the comparison. Both Core §45 sentences now name the core edge store. AC11 adds `remove-extension-edge`, which raises no core-tuple violation. |
| Q78 — observable storage behaviour | New tuples are appended as block-sequence entries in request order. For a block list, the bytes up to the last existing entry, including comments, are unchanged, and trailing comments follow the new entries. Empty and flow lists become block lists that keep the existing order. AC14 covers the block, empty and flow forms with two tuples per request. pg1 sorts tuples anyway (Core §56), so stored order carries no meaning; the rule keeps mutation diffs minimal and deterministic. |

Rejected alternatives:
- Q77, treating every `supersedes` tuple as core-immutable wherever stored. That would override the owning semantics that Core §45 grants Extensions for their own data.
- Q78, sorting on write. Every mutation would then produce unrelated diff noise.

## Challenge plan and why

The risk is an implementation that enforces uniqueness only on the five core relations, or that freezes Extension-owned stores against their owner's authority.

- **Wording checks:** compared R02, R04 and R08 against Core §15 L573–L575 and §45 L1407–L1409.
- **Placement agreement:** checked the Q77 answer against Core §54's placement sentence.
- **Diff check:** the only Core §45 wording change is the name of the core edge store; the old sentence has been replaced, not qualified.
- **Mechanical checks:** YAML parse and `contracts:check`.
