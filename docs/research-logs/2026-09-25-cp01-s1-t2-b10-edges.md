# CP01 Stage 1 T2 — B10: Typed edges

**Scope and authority:** see [B7](2026-09-25-cp01-s1-t2-b7-checkpoint-obligations.md). Starting revision `939f2b5`. Depends on B9's record model. Keeps the PR #41 B3 decisions (Q10–Q13, Q19).

**Owners:** Core §§15, 45, 54; Distribution §§10, 15. Affected: CP01-S03 R01, R02, R04, R08, AC02, AC04, AC11 and the new AC14; Core §45 (v4).

| Question / classification | Answer and rationale |
|---|---|
| Q76 — already specified; coverage missing | Core §15 applies endpoint existence and tuple uniqueness to all relations. R02 and R04 now say so. AC02 adds two missing-endpoint cases on an additional relation, and AC04 gets `core-relation` and `additional-relation` cases. |
| Q77 — ambiguous | Core §45 immutability covers every tuple in the core edge store `specs/graph/edges.yml`. Tuples in an Extension edge file follow that Extension's semantics and its Distribution §10 preservation and deletion authority. This includes its same-type `supersedes` tuples. This follows Core §54's placement rule (the relation owner, or for `supersedes` the endpoint-type owner) and §45's "Extension-owned data has its owning semantics". Core §45 now names the store. AC11 adds `remove-extension-edge`, which raises no core-tuple violation. |
| Q78 — observable storage behaviour | Adding tuples keeps existing entries in their stored order and appends the new ones. A block-list file's existing entries are not reformatted. New AC14 covers a block list with a comment and non-sorted tuples, and an empty list. pg1 sorts tuples anyway (Core §56), so the stored order carries no meaning. The rule keeps diffs reviewable and avoids rewriting conforming files (Distribution §15). |

Rejected alternatives:
- Q77, treating every `supersedes` tuple as core-immutable wherever stored. This would stop an owner from exercising its Distribution §10 deletion authority over its own store.
- Q78, sorting on write. This rewrites conforming files, and every mutation would then produce unrelated diff noise.

## Challenge plan and why

The risk is an implementation that enforces uniqueness only on the five core relations, or that freezes Extension-owned stores against their owner's authority.

- **Wording checks:** compared R02, R04 and R08 against Core §15 L573–L575 and §45 L1407–L1409.
- **Placement agreement:** checked the Q77 answer against Core §54's placement sentence.
- **Diff check:** the only Core §45 wording change is the name of the core edge store; the old sentence has been replaced, not qualified.
- **Mechanical checks:** YAML parse and `contracts:check`.
