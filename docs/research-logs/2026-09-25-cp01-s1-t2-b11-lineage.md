# CP01 Stage 1 T2 — B11: Lineage derivation

**Scope and authority:** see [B7](2026-09-25-cp01-s1-t2-b7-checkpoint-obligations.md). Starting revision `d520b76`. Dependencies: B8 (incomplete-load categories), B9 (records), B10 (edges). The PR #41 B4 decisions Q14–Q16 are kept.

**Owners:** Core §§44, 45, 57. Affected: CP01-S04 R06, AC07 and the new AC11–AC12; CP01-S16/AC13.

| Question / classification | Answer and rationale |
|---|---|
| Q79 — already specified; coverage missing | Core §44 cardinalities apply to every stored record, and Core §57 names "missing required lineage". A record that no Intent reaches is reported as missing required lineage and named. It changes no Intent's result, because it belongs to none, so a per-Intent failure would have to guess its owner. R06 states this, and AC11 has one case per record kind plus an unaffected-Intent control. |
| Q80 — missing observable | After an incomplete load, every derived result carries a diagnostic-only, non-executable marker. AC12 uses a malformed lifecycle file and a missing lock with a complete-load control. The marker's representation is an implementation choice; its presence is observable. |
| Q81 — already specified; coverage missing | Core §44 "when one exists": a first authorisation after defer creates a Contract without a Contract supersession. AC07 adds `first-proceed-after-defer`, which yields contracted with no missing-supersession problem. The existing AC06 negatives still cover omitted supersession when a last Contract exists. |
| Q82 — traceability error | S16/AC13 now maps each case name to its CP01-S04 scenario: AC01 done, the AC06 standalone control, AC06 two-current-briefs, and AC07 proceed-to-reject. |

Rejected alternatives:
- Q79: failing the whole graph for one unreachable record. This contradicts Core §44's per-Intent derivation.
- Q79: silently ignoring the record. This contradicts Core §57.
- Q81: requiring a supersession edge on every re-authorisation. This contradicts "when one exists".

## Challenge plan and why

The risks are an implementation that rejects the valid first authorisation, one that hides unreachable records, and a later consumer (S16) that cannot find its referenced scenarios.
