## Probe and challenge plan

The risk is implementations that pass every existing vector while sorting with `localeCompare` or by code point, or while printing numbers non-canonically. The probe question, stated before running, was: do the repository's Node serialiser and an independent Python RFC 8785 serialiser (UTF-16 key order, ES number formatting) produce identical bytes and digests for these inputs?

- The Python serialiser first reproduced all 7 existing vectors.
- A first Python number formatter mis-printed a large integer-valued float. That value lies outside the Core safe-integer domain; after correcting the formatter, Python and Node agreed on 14 number forms. The fixture excludes out-of-domain values.
- The Python output was written to the fixture. `tests/graph-revision-vectors.test.ts`, the Node serialiser with a js-yaml Core-schema projection of the stored bytes, passed both new vectors (10/10).
- Discrimination check: `localeCompare` ordering and code-point ordering both produce bytes that differ from `utf16-order-mixed-owners`.

The vectors are definition fixtures, not runtime acceptance evidence, and must not be regenerated from the implementation under test.
