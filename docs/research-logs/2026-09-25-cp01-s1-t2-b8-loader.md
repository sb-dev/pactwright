| Question / classification | Answer and rationale |
|---|---|
| Q61 — missing (the Stage 1 part of Q30/Q47) | Each problem carries a path, a cause and a category. The load result must distinguish at least: missing/unreadable, malformed, unsupported version, migration-required, unexpected entry, non-core entry in core storage, inactive component and unavailable enabled Extension. This refines Core §57's "malformed / unsupported-inactive / unavailable" split to the level S09 and S18 already need. Category names, exit codes and severities remain S09/S18 decisions (Q30/Q47). New S01/AC13 gives each category its own case, and one control: an inactive component alone leaves the load complete. |
| Q62 — already specified | Core §54 and Distribution §15: a blank or null edge document is migration-required, not malformed and not an empty graph. The two cases move from AC09 (generic incomplete result) to AC12 (released formats), which states the disposition. |
| Q63 — ambiguous | A non-core record type or relation tuple in core storage is always a "non-core entry in core storage" error, naming the type or relation, with bytes preserved and the load incomplete. The migration prerequisite is that its owning Extension be enabled and registered. The loader never guesses whether the entry is legacy Extension data or a typo: before registration, both carry the same accurate diagnosis. Owner resolution is S03/AC13 (registered fixture owners) and the S19 migration planner. This satisfies both Core §15 (unknown active type is an error) and Core §54 (legacy placement is reported, never moved). |
| Q64 — dependency error | `unexpected-active-extension-entry` moves to CP01-S03/AC13 in this batch, which has fixture owners from the S02 seam. S01 keeps `requires: []` and the owner-independent `specs/extensions/` top-level cases. |
| Q65 — ambiguous | Every AC11 case runs once in each YAML input kind (configuration, lifecycle, lock, core-record frontmatter, edges), each with its own result. |
| Q66 — ambiguous | GitHub-enabled configuration gives a complete load with a non-blocking notice that remote operations are unavailable (Core §54: "inert … without disabling otherwise supported local graph inspection"). An incomplete load would wrongly block S05 hashing. |
| Q67 — missing case | Add AC04 `stale-build`: rebuild the same target or fail explicitly; never run stale output. |
| Q68 — missing cases | Add AC09 `symlinked-specs-ancestor`, `symlinked-pactwright-directory` and `non-empty-gitkeep` (Core §54). |
| Q69 — contradiction / missing output | The loader is read-only (Core §54 "Loading never … writes files"). S11/R06 now reads through the loader and writes through the command's own serialiser, verified by loader read-back. S01's load result lists every input path with exact bytes and decoder (R05, AC05). S02's registry exposes a deterministic registry identity (R09, AC12 `registry-identity`). Together they supply the S07/R06 stale-base inputs. |
| Q42 — missing requirement (Stage 1 part) | Plain init writes a version 1 lock with no `agent_pack` (Distribution §12, amended). That lock is complete and valid for loading and pg1; only capability execution waits for a pack. S01/AC05 adds `lock-without-agent-pack`. S14/R01 now lists the lock and lifecycle files, and S14/AC02 expects a complete load with a pg1 revision. |

Rejected alternatives:
- Exempting a missing lock in a scaffold from Core §§54/56. That would create two load modes and make "missing lock" ambiguous.
- Labelling unknown types in core storage as migration-required by default. That hides typos as legacy data.
- A loader write API. It contradicts the read-only loader and blurs command ownership.

## Challenge plan and why

The risks are two reasonable loaders giving different labels or completeness for the same input, a case moved without its obligation, and a Stage 4 contract left contradicting the new lock rule.

- **Case preservation:** a set difference of S01 case names before and after showed one removal, `unexpected-active-extension-entry`, now in S03/AC13; the blank and null edge cases moved from AC09 to AC12.
- **Owner consistency:** checked the new AC12 wording against Core §15 L577 and §54 L1663–1665, and Distribution §15 table rows.
- **Q42 consistency:** grep for "lock" in S05/S14/S15; S14/R01 and AC02 were the only conflicting statements. S15's no-pack environment is still incomplete for capability resolution, which the new Distribution §12 sentence states.
- **Q69 consumers:** grep for "loader" in S07–S19. S11/R06 and AC09 were the only write-through-loader claims.
- YAML parse of every contract, and `contracts:check`.
